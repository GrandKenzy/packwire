Windows 10/11: Solución al Falso Positivo de as.exe en GCC

¿Por qué Windows Defender elimina el archivo as.exe y cómo resolverlo en segundos.

Exclusivo para entornos Windows
🛡️ ¿Qué está ocurriendo?

En GCC / MinGW (distribuido a través de w64devkit), as.exe es el GNU Assembler oficial. Al compilar código C o C++, GCC invoca este programa para transformar código fuente en archivos binarios.

Los motores de inteligencia artificial y protección en tiempo real de Windows Defender en Windows 10/11 pueden identificarlo como un falso positivo (comúnmente Trojan:Win32/Wacatac.B!ml o Trojan:Win32/Phonzy) y bloquear su extracción, causando el error gcc: fatal error: cannot execute 'as': CreateProcess: No such file or directory.

1 Verificación segura con Packwire

Packwire verifica el SHA-256 del release oficial y no desactiva Defender ni añade exclusiones automáticamente. Si el bloqueo persiste, conserva la protección activa y envía el archivo al análisis de Microsoft como posible falso positivo.

2 Revisar el bloqueo en Seguridad de Windows

Abre Seguridad de Windows > Protección contra virus y amenazas > Historial de protección. Solo restaura un archivo después de validar su hash y su origen oficial.

3 Recuperar as.exe si ya fue puesto en cuarentena

Si Windows Defender ya bloqueó el archivo, revisa el registro y restáuralo solo después de validar el hash y el origen oficial:

  1. Presiona la tecla Windows y busca Seguridad de Windows.
  2. Entra en Protección contra virus y amenazas.
  3. Haz clic en Historial de protección.
  4. Busca la amenaza detectada recientemente (mencionará Trojan:Win32/Wacatac... o la ruta de as.exe).
  5. Haz clic en el registro, presiona el botón Acciones y selecciona Restaurar o Permitir en el dispositivo.
4 Reinstalar GCC limpiamente

Después de resolver el bloqueo, reinstala el paquete de C/C++ para volver a descargar el release estable:

packwire reinstall c-gcc

Para comprobar que GCC funciona correctamente con su ensamblador:

gcc --version
